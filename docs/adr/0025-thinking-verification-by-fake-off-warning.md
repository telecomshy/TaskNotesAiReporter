# 「思考」验证收敛为生成期假关告警：不设测试按钮，自定义模型不提供开关

ADR-0024 取「能力表为默认种子 + 测试按钮实测定论」，自定义供应商走「思考参数名 + 测试按钮」。实施到 #85 设计时发现两件事：暗号字段要求用户具备厂商文档级知识（多数用户不知道该填 `enable_thinking` 还是 `thinking`）；测试按钮要消灭「假 ✅」（乱填字段 + 本就不思考的模型会被判生效）须引入双请求基线对照，复杂度与收益不成比例。据此收敛：**任何供应商都不设「测试」按钮**，验证能力表的职责归 #84 已落地的**生成期假关告警**（设「关」发出关参数而响应仍带推理段 → 一次性非阻断告警）与研究笔记的取证维护；**自定义供应商模型不提供「思考」开关**（三态置灰、标注「自定义供应商不支持思考开关」）——能力表按网关分派、自定义 URL 猜不得（同名模型在不同网关暗号不同，见 `docs/research/thinking-toggle-apis.md` §9.2），在意思考耗时的用户可直接换配非思考模型。

## Considered Options

- **自定义参数名 + 测试按钮（ADR-0024 原案）**：用户不识暗号字段；单请求测试有假 ✅ 歧义，双请求对照又过度设计——裁。
- **预设供应商测试按钮（#83 故事 17）**：五家预设的映射由内置能力表确定（随研究笔记维护），无需用户验证；「手动按钮 + 被动告警」双层防线收敛为被动告警单层——裁。
- **自动探测暗号**（测试按钮自动试多家参数）：每次多花微型请求，且属 ADR-0024 已否决的「自动探测」变体——不做。
- **置灰标注而非隐藏**：自定义模型的三态保留布局、置灰并自陈原因（与「强制思考」同款式样），比凭空少一行更可解释。

## Consequences

- 假关告警成为唯一动态防线：依赖每次生成的响应推理段读面（`reasoning_content` / `reasoning_tokens`，#84 已实现）；能力表错误只能事后以告警暴露，不能事前验证。
- 能力表的正确性义务加重：更新必须随 `docs/research/thinking-toggle-apis.md` 取证（版本锚点与实测对照由研究笔记承载）。
- 自定义供应商用户失去插件内的思考优化路径，换配非思考模型是唯一出路；「思考参数名」字段与纯模块 `customParamName` 输入随裁。
- 400 拒收仍归 `ai-error` 上浮、不降级重试；默认「关」、三态、能力表、一次请求只发一个开关参数、假关判定均不变（ADR-0024 保留）。
- 取代 ADR-0024 的「测试按钮实测定论」与「自定义供应商填参」两节；其余各节保留生效。
