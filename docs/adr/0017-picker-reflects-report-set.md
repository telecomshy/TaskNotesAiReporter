# 选择任务窗口反映报告集合，确认只提交可见差异

> 本 ADR 的「独立选择窗口 + 确认差异」模型已由 [ADR-0019](0019-inline-task-selection.md) 取代；「确认只提交当前可见任务的差异」与「筛选变化会按默认规则重算勾选」先由 [ADR-0018](0018-picker-selection-is-manual.md) 取代。主列表即报告集合的核心不变。

「选择任务」窗口原先只呈现尚未「已加入」的任务（ADR-0004 / ADR-0011）。用户加入一批任务后再次打开窗口、选择同一筛选，列表为空，无法回顾或调整已有选择。决定：窗口按当前筛选呈现任务，已加入任务默认勾选；取消勾选一个可见的已加入任务并确认，会把它从主列表移除。确认只提交当前可见任务的差异——未出现在当前筛选里的已加入任务不受影响。

## Considered Options

- **只回显、禁用复选框**（#1 / #3 的做法）：已加入任务可见但点不动；#9 已因“看似可选、实际不可操作”否掉。
- **只呈现可加入任务**（ADR-0011 的做法）：窗口保持纯追加面，但用户每轮都要回主窗口移除任务，且无法确认自己已加入什么。
- **窗口维护完整集合、确认时整体覆盖**：筛选会隐藏任务，整体覆盖会把当前筛选之外的已加入任务一并删掉，属操作性错误。

## Consequences

- `PickerSession` 携带全部任务与 `candidateIds`；`desiredIds` 初始为 `candidateIds`，可见任务包含已加入任务。
- 时间页仍自动勾选可见的新任务；标题页仍只预选已加入任务，不自动勾选新任务。
- 新增 `pendingChanges` 计算当前可见任务的新增 / 移除；`summarizeChanges` 提供计数视图，`hasDesiredVisible` 提供「清空选择」的禁用依据；`ReportModal` 按差异更新主列表。
- 有移除时确认按钮显示 `+新增 / −移除`；仅新增时仍显示「加入列表（N）」。
- 筛选变化会按默认规则重算勾选，未确认的取消不跨筛选保留；这是为避免“看不见的任务被误删”而选择的保守行为。
- 部分取代 ADR-0004 中「选择窗口只呈现尚未已加入的任务」的结论与 ADR-0011；「主列表即报告集合」的核心不变。
