# 选择任务的勾选只由用户操作改变

> 「暂存勾选 + 确认差异」的模型已由 [ADR-0019](0019-inline-task-selection.md) 取代；「筛选只改呈现、勾选只由用户操作改变」的结论仍有效。

「按标题」筛选下勾选一个搜索结果后改变搜索词，勾选会被清空——`setQuery` 按 ADR-0017 的默认规则用「已加入 + 当前可见」重建了勾选集合。同类问题也存在于切 Tab 与改时间区间：前者会丢掉未提交的新增勾选，后者会把用户手动取消的已加入任务重新勾上。用户预期是：勾选是一份跨筛选的意图，只有自己点复选框、全选 / 清空才能改变它。决定：`desiredIds` 只由构造初值与用户操作推进；`switchTab` / `setQuery` 只改呈现，`setRange` 只追加当前区间内可见、且未被用户手动取消的「可加入」任务（时间页的批量挑取入口），绝不移除或重勾已加入任务。确认时 `pendingChanges` 对 `desiredIds` 与 `candidateIds` 求全量差集，跨筛选累计的勾选一并提交。

## Considered Options

- **保持 ADR-0017 的「筛选变化重算勾选」**：勾选随视图丢失或复原，正是本次缺陷。
- **保留勾选，但仍只提交可见差异**：跨筛选累计的勾选不会进入确认结果，按钮计数漏算、甚至因当前无可见差异而禁用，用户勾了却不生效。
- **记录「用户手动改过的 id」，让筛选重算时跳过这些任务**：能保留时间页默认全选，但多一份状态与规则。最终只取最小版本——记录 `manuallyUncheckedIds` 供区间自动勾选跳过，其余筛选转移仍完全不写勾选。

## Consequences

- `pendingChanges` 遍历全部任务，不再只看可见任务；`PickerChanges` 的语义是「勾选集合相对已加入的差集」。
- 不再需要「防止看不见的任务被误删」的可见性保护——筛选已不改动勾选，隐藏的差异只可能来自用户操作。
- 时间页改区间仍自动勾选当前区间内可见、且未被用户手动取消的「可加入」任务；已加入任务的勾选状态保持不变。用户手动取消的可加入任务记入 `manuallyUncheckedIds`，换区间再回来也不会被重新勾上；手动重新勾选会解除抑制。
- 「全选」「清空选择」仍只作用当前可见任务；当前筛选外的勾选 / 取消仍计入确认。隐藏的差异只能从确认按钮的计数看到，列表徽标只在任务可见时显示。
- 部分取代 ADR-0017 中「确认只提交当前可见任务的差异」及「筛选变化会按默认规则重算勾选」的结论。
