# 日期口径默认勾选遵循「期间内发生或安排的活动」

#80 给「日期口径」新增修改时间（`dateModified`）时定下了默认勾选集：完成、修改、创建、计划默认勾选，到期（`due`）默认不选。裁决依据是「默认口径 = 期间内发生或安排的活动」这条产品原则，但它当时整段写在 `CONTEXT.md` 的「日期口径」术语词条里——词汇表不是决策记录，词条随编辑漂移，代码里无可引出处。决定：**默认勾选集的原则与论证移居本 ADR**，`CONTEXT.md` 词条只留术语定义与一句指回；`DEFAULT_SETTINGS.dateFields` 继续显式列字段名（默认集是产品决策，不从日期口径清单派生，见 #81）。

原则：**「日期口径」的默认勾选 = 期间内发生或安排的活动**。口径字段分两类：

- **事件时间戳型**（创建 `dateCreated` / 修改 `dateModified` / 完成 `completedDate`）：记录事件实际发生在何时。事件落在期间内就是「期间内发生的活动」，默认勾选。
- **指向型**（计划 `scheduled` / 到期 `due`）：指向任务被安排或被要求在何时。计划是「期间内安排的工作」，属活动，默认勾选；到期是**纯期限指向**——一个截止约束，不表示期间内有任何活动发生或被安排（赶在期限前做完的工作，其活动落在完成时间上），默认**不勾选**，用户可手动勾选。

将来新增日期口径按此原则裁决默认勾不勾；与原则相悖的例外须在此记录并说明理由。事件时间戳型 / 指向型这组分类学目前**不**升格为 `CONTEXT.md` 正式术语——它的论证家在本 ADR，留待第二个真正用到该分类的地方再议（#81 明确不升格）。

## Considered Options

- **原则留在 `CONTEXT.md` 术语词条**（现状）：词条随编辑漂移，且词汇表装产品决策正是 #80 审查判出的结构性欠账，放弃。
- **不立 ADR，只做词条瘦身，决策留 issue（#80）**：成本最低，但下一次「新口径默认勾不勾」仍无可引出处；立本 ADR 的目标正是让裁决有据可依，放弃。这是本 ADR 不够格时的既定回退方案。
- **默认集从清单派生**（按字段类型自动定默认）：把产品决策藏进推导逻辑，改默认要动结构；默认集显式列在 `DEFAULT_SETTINGS` 更直白，放弃。
- **分类学升格为 `CONTEXT.md` 正式术语**：目前只有一个用户（本 ADR 的论证），分类学的家在论证里而非词汇表，本次不升格。

## Consequences

- `CONTEXT.md`「日期口径」词条瘦身为术语定义（五字段清单、命中任一即纳入、全不选＝自动筛选关闭）+ 一句指回本 ADR。
- 新口径的默认勾选裁决引用本 ADR；默认集变更仍是独立产品决策，只改 `DEFAULT_SETTINGS.dateFields`。
- ADR 三准则中「难逆转」一条对默认值决策偏弱（改默认成本低），以仓库先例 [ADR-0007](0007-english-defaults-and-example-template.md)（默认值决策型 ADR）与「该原则是将来每次新口径默认裁决的依据」补位。
- 来源：#80（原则与默认集的产生）、#81（移居 ADR 与词条瘦身）。
