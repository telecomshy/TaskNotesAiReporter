# 模型请求策略：方言之上的第二层窄化

> 规格见 issue #106。与 [ADR-0028](0028-api-dialect-as-provider-property.md)（接口方言是供应商属性）衔接；
> 本 ADR **只修订** ADR-0028 里「请求体参数策略由方言固定」这一句——方言仍是基线，
> 模型请求策略只能在其上窄化，不能加回方言已删的参数。

## Context

2026-11-26 调研（`docs/research/openai-official-preset.md`）确认：OpenAI 官方同一家供应商内部，
模型参数规矩就不一致——`temperature` 在 `GPT-6.2` 恒不可传、在 `GPT-5.2/5.4` 只在
`reasoning_effort: "none"` 时可传、在旧非推理模型上可传；`reasoning_effort: "none"` 在
`GPT-6 Astra` / `GPT-6.1 Sol` / `GPT-6.2` 上直接 400；`max_completion_tokens` 才是官方定义的
「含推理 token 的输出预算」，且官方建议起步预留 25,000 token。方言是供应商级属性（ADR-0028），
装不下同一供应商内部的模型级差异；不引入第二层，唯一出路是客户端特判或第三种方言。

## Decision

1. **新增内置只读数据表** `src/core/requestPolicy.ts`，行键 `(供应商 id, 模型 pattern)`，与
   `THINKING_CAPABILITIES` 同构；输出「输出额度字段名 / 温度规则 / 输出预算下限 / 超时下限」。
   事实源是研究笔记，随版本维护，无用户配置面。
2. **分层语义：方言定基线，模型请求策略只能窄化**——允许删掉该模型不接受的参数（如温度）、
   抬高预算与超时下限；不允许加回方言已删的参数（Anthropic 方言永不发温度，任何策略行也加不回来）。
3. **只对内置预设按 `providerId` 命中**。自定义供应商与四家现有 OpenAI 兼容预设零变更；
   不按地址嗅探 `api.openai.com`（代理 / 自建网关会被误伤）。
4. **OpenAI 官方预设本轮只走 Chat Completions**。`*-pro`、`gpt-oss-*`、`gpt-5.6-cyber` 属
   Responses-only，不进清单；Responses API 单开待办票（`max_output_tokens` / `output[]` 是另一套请求与解析）。
5. **不新增用户界面**。温度 / 最大输出 / 超时本就无可视设置；策略是插件内置数据，预设卡与其它预设外观一致。

## Considered Options

- **在供应商对象上加 `requestPolicy` 字段**：预设也持久化，策略会被用户数据污染、无法随版本修正——否。
- **提高全局默认 `maxTokens`（8192 → 32k）**：四家国产预设跟着变，违反 #105 的「OpenAI 方言零变更」——否。
- **新增第三种方言「OpenAI 官方推理」**：同一供应商里推理 / 非推理模型混用，方言是供应商级属性，装不下模型级差异——否。
- **按地址嗅探官方端点**：地址是可改的配置，代理与自建网关会被误套；用户也无法解释为何同一地址换个写法行为就变——否。
- **本轮就实现 Responses API**：纯文本单轮 Chat Completions 已覆盖当前全部 GPT-6 文本模型（含 GPT-6.2），
  多一套请求体与解析的收益只是拿到 `*-pro` / `gpt-oss-*`——暂不做，单开票。

## Consequences

- **表会漂移**：OpenAI 新模型族上市时，策略行与清单规则都要随插件更新（与思考能力表同一维护流程）。
- **温度判定依赖本次实际 effort**：开 → 发开参数（取值见规格）、关 → 发 `none`；对拒绝 `none` 的族关态不发参数，
  实际 effort 是默认 `medium`，因此仍须省略温度——「能不能发温度」按模型族 × 生效 effort 判定，不按用户开关判定。
- **预算下限只对推理族生效**：下发 `max(全局上限, 25,000)`；非推理老模型沿用全局值。
- **超时下限没有官方依据**：官方未公布典型延迟或建议超时，120 秒是产品判断（研究笔记已写明 not verifiable），
  取值偏保守；用户全局值更大时取更大。
- **清单过滤在拉取解析处**：OpenAI 官方预设的「模型清单」只含可对话模型，挑选框与「已失效」判定都只面对可用集；
  过滤名单的具体形态见规格。
- **不新增错误码 / 状态语义**：仍用 `chat.*` / `models.*` / `timeout` 现有词表。
