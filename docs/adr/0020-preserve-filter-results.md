# 左栏保留筛选结果，已加入项只加标记

[ADR-0019](0019-inline-task-selection.md) 把选择区并入主弹窗后，左栏只显示尚未「已加入」的「可加入」任务。实际使用中，加入一个任务会让它从左栏消失，左栏不再是稳定的筛选结果：用户无法对照「筛选命中了什么」与「报告里有什么」，列表行数与「可加入」计数也不再一致。决定：左栏呈现当前筛选命中的全部任务（筛选结果），已加入项留在原位、只加「已加入」标记且不可点；可加入项仍整行点击加入；右栏仍是报告集合，整行点击（「－」）移除，是唯一的移除入口。计数改为「筛选结果 M · 可加入 N」。删除「全部已加入」空态；左栏只在未选区间 / 无命中时为空。

## Considered Options

- **维持只显示可加入（ADR-0019）**：动作列表最纯，但左栏随加入而跳动，无法对照筛选结果与报告集合，计数与行数也对不上。
- **已加入项在左栏也可点击移除（对称 toggle）**：交互对称，但打破「右栏是唯一移除入口」，且误点会直接删掉报告任务。
- **左栏分「可加入 / 已加入」两段**：保留动作清单，但把筛选结果拆成两段，并与右栏重复，顺序也不再是筛选顺序。
- **左栏保留筛选结果 + 惰性标记（本决定）**：列表稳定、可对照；代价是左栏出现不可操作行，需要标记与 tooltip 解释。

## Consequences

- `CONTEXT.md` 新增「筛选结果」，并把「可加入」改为筛选结果的子集；「选择任务」定义同步。
- `selectionSession.leftEmptyReason` 去掉 `all-joined`；左栏渲染 `matchingTasks`，用 `isJoined` 区分惰性行；`addableTasks` 仍供计数与批量加入。
- 右栏交互不变；移除后左栏对应行恢复为可加入。
- 部分取代 ADR-0019 的「左栏只显示可加入」与 ADR-0011 的「只呈现尚未已加入」；ADR-0019 的合并、直接转移、右栏唯一移除入口、筛选不改报告集合仍有效。
- 不引入暂存勾选；报告集合仍只存在于当前弹窗生命周期。
