# 状态筛选是独立筛选维度：归类三档 chips，不进标题查询

「选择任务」左栏要按任务状态快速收窄「筛选结果」。决定：新增**状态筛选**为第三个筛选维度，与「筛选区间」「标题查询」并列、叠加为 AND，两个页签共享一行常驻 chips（三档多选：待办 / 进行中 / 已结束，档间 OR，全不选＝不过滤）；**不**把状态写进标题查询语法（[ADR-0003](0003-title-search-matching-semantics.md) 的三维度不动）。

三档是「状态归类」的投影，不是 TaskNotes 状态的镜像：目录内状态按 [ADR-0015](0015-status-classification-owned-by-adapters.md) 的规则折叠（`isCompleted` → 已结束；值名 `in-progress` → 进行中；其余 → 待办），悬空值（改名 / 删状态残留）→ 「未知」。「未知」不设 chip：只在全不选时出现，选中任一档即被排除，并在结果区提示「另有 N 条状态未知的任务未显示」——消失必须可见。状态目录为空时 chip 禁用（不隐藏）。筛选只改左栏呈现，报告集合与「已加入」顺序不受影响。

**位置**：chips 行在页签栏之下、两页专属筛选控件之上，跨页签恒定、切换不重建——位置本身表达「共享维度」的语义。形态经原型裁决（A 恒定 chips 行 / B 页内控件 / C 漏斗下拉，原型 `src/ui/prototype-status-filter-placement.html` 留存于 throwaway 分支）：取 A，C 留作筛选维度变多时的演进路径。

## Considered Options

- **写进标题查询语法（`!done` / `status:done`）**：与 ADR-0003 同构、可组合，但把状态筛选锁死在「按标题」页——状态是任务属性，「按时间」页同样需要；还要发明第四个维度的前缀记号，自定义状态值名带中文 / 空格时解析麻烦。
- **页内控件（chips 融进各页筛选区，随页签重建）**：贴合语境，但传达「只属于当前页」的错误语义，切页签位置跳动——ADR-0020 刚确立「左栏稳定、可对照」，不再造跳动。
- **漏斗下拉（popover 勾选）**：省空间、可扩展，但活跃筛选藏在角标里，用户会忘记"筛着呢"，任务「消失」不可见——与 ADR-0020 的教训相悖。
- **chips 出动态状态值（按目录逐值）**：可精确筛自定义状态，但选项随用户状态数膨胀，且同样躲不开改值名后的悬空（改 `value` 不迁移任务笔记，见 [research](../research/tasknotes-plugin-fields-statuses-api.md) 第 5 节）。
- **插件设置里配「状态 → 归类」映射（按状态 `id`）**：彻底抗改名，但多一块设置面与迁移负担；立为独立需求，不在本次。
- **列表加属性列 + 排序**：排序不解决筛选诉求（"只看已结束"仍要滚屏）；右栏「已加入」顺序是语义（ADR-0019/0020），排序与之冲突。

## Consequences

- `CONTEXT.md` 新增「状态筛选」；「未知」之牙沿用 ADR-0015：认不出的状态绝不谎报进「待办」或「已结束」。
- 「进行中」判定沿用值名 `in-progress` 的已知限制（ADR-0015）：用户改名后该档失效、任务折叠进「待办」，报告的 `{{inProgressTasks}}` 子集同样受影响。筛选与报告喂料共用同一份映射（`core/status.ts`），不分裂；chip 悬浮提示说明折叠规则。
- 已知限制如实进规格并文档化：自定义状态折叠进三档；悬空值 → 未知；`cancelled`/`isSkipped` 类状态归「待办」并进报告未完成子集（超出本次范围，单独立项）。
- 状态目录（`repository.statuses()`）注入选择会话；状态筛选逻辑落纯函数层，与 `filterTasksBySubset` 同源。
- 「加入全部」与「筛选结果 M · 可加入 N」计数严格跟随当前筛选；不引入跨弹窗持久化（ADR-0019）。
- 不承诺通用「属性筛选」框架；按优先级等其它属性的筛选将来另议。
