# 非供应商设置同样经命令门面，变更时维护不变式

供应商配置已有深且可测的命令门面 `providerSettings`，其不变式在**变更命令处**维护、而非载入时校验（ADR-0010）。但通用 / 报告设置（报告目录、日期口径、周起始、报告语言、界面语言、模板与所选模板）没有对应门面：视图直接改 `plugin.settings.X` 并各自落盘，载入侧的组合（归一 → 迁移明文密钥 → 按需落盘 → 建门面）埋在插件入口里、无测试。决定：给这块切片也建一个命令门面 `appSettings`，持久化与变更时不变式归它（trim、报告语言空回退、界面语言归一、所选模板必须存在）；并把载入组合抽成接受注入 IO 的 `loadSettings`，使其可测。

## Considered Options

- **只抽 loader、不建门面**：载入可测，但视图仍直接改设置、持久化仍散落，变更时不变式仍无归属。
- **按关切拆两个门面（通用 / 模板）**：接口更小，但接缝更多；`providerSettings` 的先例是「一个切片一个门面」，故不拆。

## Consequences

- 三个设置 Tab 与生成弹窗不再直接改 `plugin.settings`，改走门面命令。
- `removeTemplate` 清理悬空的 `selectedTemplateId`（顺带修复 #33）。
- `CONTEXT.md` 不新增词条（设置不是域概念）；本 ADR 把 ADR-0010 的「变更时不变式」模式推广到整个设置切片。
