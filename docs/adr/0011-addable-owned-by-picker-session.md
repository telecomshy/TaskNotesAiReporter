# 「可加入」的排除规则归选择任务会话，而非主窗口

> 本决定已由 [ADR-0017](0017-picker-reflects-report-set.md) 部分取代：「可加入」仍作为域词存在，但选择窗口不再隐藏已加入任务。独立窗口随后由 [ADR-0019](0019-inline-task-selection.md) 合并进主弹窗：左栏只显示可加入任务，右栏显示全部已加入任务，因此「可加入」的排除规则仍归选择会话。左栏呈现随后由 [ADR-0020](0020-preserve-filter-results.md) 修订为「保留筛选结果，已加入项只加标记」；「可加入」仍由选择会话派生。

「选择任务」窗口只呈现尚未「已加入」的任务。该排除规则原先由主窗口在打开窗口前先行过滤（`src/ui/taskSelection.ts` 的一行模块）。决定：把它折进选择任务会话——会话在构造时接收「全部任务 + 已加入路径集合」，派生「可加入」集合，使可见 / 可勾选 / 可加入同属一个模块。理由：`CONTEXT.md` 对「选择任务」的定义本就以「只呈现尚未『已加入』的任务」界定，规则属域内该窗口；独立的一行模块接口与实现同宽，删除它使选择规则**集中**而非搬家。取代 issue #31 中「`getAddableTasks` 留守独立模块」的选择。

## Considered Options

- **只删浅模块、把过滤内联进主窗口**：同样删掉一行模块，但不集中选择规则（复杂度只是搬回调用方），且丢掉那几个平凡测试。
- **维持现状**：保留独立模块。因该模块是穿透层、且规则在域上属 picker，故不取。

## Consequences

- `pickerSession` 的 `allTasks` 字段更名为 `addableTasks`（语义已不是「全部任务」）。
- `TaskPickerModal` 构造改为接收「全部任务 + 已加入集合」，`ReportModal` 不再先行过滤。
- `src/ui/taskSelection.ts` 及其测试删除；「可加入」作为域词进入 `CONTEXT.md`。
