# 选择任务合并进主弹窗，报告集合与筛选结果直接转移

「选择任务」原先是独立弹窗，并在报告集合与筛选结果之间维护第三份「暂存勾选」：主窗口持有报告集合，选择窗口持有 `desiredIds`，确认时再提交两者差异。这套模型反复出问题——筛选变化要不要重置勾选、确认只提交可见还是全量、跨筛选勾选看不见——因为暂存层的生命周期本身就是额外的状态机。决定：把选择任务并入生成报告主弹窗，做成左右两栏；左栏是纯筛选结果（只显示尚未「已加入」的「可加入」任务），右栏是报告集合（按加入顺序）；左栏勾选即加入右栏，右栏是唯一的移除入口；筛选只改左栏呈现。删除暂存勾选、差异提交、确认步骤、已加入 / 将移除徽标和独立选择弹窗。「生成报告」直接读取右栏集合，关闭弹窗仍整体放弃。

## Considered Options

- **保留暂存层，补一个「筛选外变更」面板**：只解决隐藏差异的可见性，暂存层、差异提交和筛选语义仍然存在，下一轮仍会在同一处出问题。
- **保留双弹窗，但选择窗口直改报告集合**：能删掉暂存层和确认步骤，改动较小；但用户仍不能同时看到筛选结果与报告集合，来回切换的认知成本不变。
- **左右分栏合并（本决定）**：一次删掉暂存层与弹窗边界，两个集合同屏直接转移；代价是主弹窗布局、响应式和测试需要重写。

## Consequences

- 选择会话拥有全部任务快照、报告集合（有序）、Tab、筛选区间、标题查询与日期口径；不再有 `candidateIds` / `desiredIds` / `pendingChanges` / `manuallyUncheckedIds`。
- 左栏只显示当前筛选命中的「可加入」任务；右栏显示全部「已加入」任务。加入立即生效，移除只发生在右栏。
- 筛选转移（切 Tab、改区间、改查询）不再触碰报告集合；日期自动勾选随之消失。
- 主弹窗改为宽弹窗；窄屏用「筛选 / 已选」页签切换两栏。
- 独立选择弹窗、选择专用会话、徽标、确认文案与相关样式删除；`TaskPickerModal` 不再存在。
- 「主列表即报告集合」（ADR-0004）的核心不变；报告生成、模板、来源探测不变。
- 部分取代 ADR-0017 与 ADR-0018 中关于暂存勾选、筛选重算与差异提交的结论。
- 不引入跨弹窗持久化；报告集合仍只存在于当前弹窗生命周期。
