# 规格：选择任务支持按「状态归类」筛选（状态筛选）

> 权威出处：GitHub issue [#75](https://github.com/telecomshy/TaskNotesAiReporter/issues/75)（`ready-for-agent`）。本文件是仓库内可被 `/code-review` 直接发现的副本。
>
> 出处：`/grill-with-docs` 逼问定形（2026-10-28），经原生 **`/to-spec`** 流程重写（测试接缝已经用户确认）。形态经原型裁决（A 恒定 chips 行 / B 页内控件 / C 漏斗下拉 → **取 A**）。决策详见 [ADR-0021](../adr/0021-status-filter-shared-dimension.md)；术语「状态筛选」已收编 `CONTEXT.md`。后续立项：[#77](https://github.com/telecomshy/TaskNotesAiReporter/issues/77)（状态→归类映射配置）、[#76](https://github.com/telecomshy/TaskNotesAiReporter/issues/76)（cancelled/isSkipped 归类）。初版手稿（FR 体例）留存于 issue #75 编辑历史。

## Problem Statement

我在「选择任务」左栏挑任务进报告集合。现在只有两种筛选方式：「按时间」给个日期区间，「按标题」搜关键字 / `#标签` / `@上下文`。可是我挑任务时最常问的问题是"**哪些还没开始？哪些正在做？哪些刚做完？**"——这三问一个都答不了：状态只显示在每行的小字里（`状态:xxx`），看得见、筛不了。几百条任务只能滚动肉眼扫，扫完还容易漏。更糟的是，我在 TaskNotes 里改过状态名之后，连"进行中的是哪几条"都对不上了。

## Solution

在「选择任务」左栏加一行常驻的状态筛选：**待办 / 进行中 / 已结束** 三个按钮。点一下，筛选结果立刻收窄到对应状态的任务；可以多选拼组合（比如「待办＋已结束」）；再点一下取消；全不选就回到全量。「按时间」和「按标题」两个页签都能用，和区间、查询叠加生效——"本周 + 只看进行中"一步到位。认不出状态的任务绝不会被谎报进任何档：它们只在全不选时出现，一旦我开始选档，列表底部会提示"另有 N 条状态未知的任务未显示"。筛选只改变左栏看什么，右栏报告集合一动不动。

## User Stories

1. 作为报告撰写人，我想一键只看待办的任务，以便在周报里如实汇报"还没开始的"。
2. 作为报告撰写人，我想一键只看进行中的任务，以便汇报"正在做的"。
3. 作为报告撰写人，我想一键只看已结束的任务，以便汇报"刚交付的"。
4. 作为报告撰写人，我想同时选中「待办」与「已结束」，以便把没做完的和刚做完的一次挑出来。
5. 作为报告撰写人，我想同时选中「待办」与「进行中」，以便只看"没做完的"。
6. 作为报告撰写人，我想再点一次已选的档位就取消它，以便快速换一种收窄方式。
7. 作为报告撰写人，我想档位全不选时自动看到全部任务，以便随时回到不过滤的全量视图。
8. 作为按时间挑任务的用户，我想在「按时间」页也能用状态筛选，以便"本周 + 进行中"一起看。
9. 作为按标题搜任务的用户，我想让状态筛选与关键字 / `#标签` / `@上下文` 叠加生效，以便"#前端 + 待办"精确收窄。
10. 作为选择任务的用户，我想切换页签后状态筛选不丢，以便来回换筛选方式而不重做选择。
11. 作为选择任务的用户，我想状态筛选的按钮位置固定不动（不随页签跳来跳去），以便形成肌肉记忆。
12. 作为使用自定义状态的用户，我想新增的状态自动落进正确的档（完成类 → 已结束，其余 → 待办），以便不逐个配置就能筛。
13. 作为改过状态名的用户，我想从 chip 悬浮提示里读到「进行中」的判定规则，以便理解为什么某些任务落在「待办」。
14. 为 vault 里有"认不出状态"任务的用户，我想在选档筛选时看到"另有 N 条状态未知的任务未显示"，以便知道它们没丢、只是不在当前筛选里。
15. 作为上一类用户，我想这些未知任务在全不选时仍能看到，以便自己判断它们算什么。
16. 作为已把任务加入报告集合的用户，我想被状态筛掉的已加入任务仍留在右栏，以便报告集合不因筛选而意外缩水。
17. 作为对照左右两栏的用户，我想行数与「筛选结果 M · 可加入 N」始终一致，以便相信眼前的清单。
18. 作为批量挑任务的用户，我想「加入全部」只带走当前筛选命中的可加入任务，以便批量操作与所见一致。
19. 作为键盘用户，我想用键盘聚焦并切换状态 chips（有 `aria-pressed` 状态），以便不依赖鼠标也能筛。
20. 作为使用英文界面的用户，我想三档显示 To do / In progress / Completed，以便不与 TaskNotes 的状态值（open / done）混淆。
21. 作为窄屏用户，我想在「筛选 / 已选」页签布局下也能用状态筛选，以便手机上同样能挑任务。
22. 作为重新打开弹窗的用户，我想状态筛选回到全不选，以便每次生成报告从干净状态开始。
23. 作为关心报告质量的用户，我想状态筛选只影响左栏显示、绝不改动报告集合，以便报告内容只由我"已加入"了什么决定。
24. 作为 TaskNotes 状态目录读不到的用户，我想 chip 明确禁用而不是筛出一个空列表，以便不被误导。

## Implementation Decisions

- 新增「状态筛选」为第三个筛选维度，与「筛选区间」「按标题」查询并列、叠加为 AND；**不**写进查询语法（「按标题」的三维度语义不动，见 ADR-0003）。
- 形态与位置：chips 多选按钮组，一行常驻，放在页签栏之下、各页专属筛选控件之上，跨页签恒定、切换不重建——位置本身表达"共享维度"的语义。备选（页内控件、漏斗下拉）与取舍记录在 ADR-0021。
- 选项口径：固定三档 = 状态归类的 待办 / 进行中 / 已结束。判定经状态目录映射（沿用既有目录判定语义），**不**匹配任何裸状态值名字符串。
- 选择语义：多选，档间 OR；全不选 = 不过滤；点已选 chip 取消；不设"全部"复位 chip（全不选即全部）。
- 「未知」归类：不设 chip。未知任务只在全不选时出现；选中任一档即被排除，并在列表底部显示弱提示条「另有 N 条状态未知的任务未显示」（N>0 且选中任一档时）。认不出的状态绝不谎报进「待办」或「已结束」（ADR-0015 的四档之牙）。
- 状态目录为空：三档 chip 禁用（`disabled` + `aria-disabled`），不隐藏，防布局跳动；任务照常浏览。
- 会话扩展：选择会话新增「状态目录」输入与「选中档」状态；沿用具名转移模式——只有一个转移改状态筛选，其余转移（切页签、改区间、改查询、加入/移除）不触碰它。三维组合在"当前筛选命中"的计算里叠加。
- 分类纯函数：按归类筛选的纯函数落在状态分类模块（与既有子集切分同居）；组合逻辑在选择会话模块。两者均无 DOM、可单测。
- 接线：主弹窗把状态目录（与报告生成同一来源）注入选择视图与会话；视图只渲染 chips 行并把点击转成会话转移。
- 界面语言：中英双份文案（ADR-0005/0007）；英文案 To do / In progress / Completed；chip 悬浮提示说明折叠规则（如「进行中 = 状态值名 in-progress 的任务」）。
- 生命周期：不持久化，随弹窗会话重建清空（ADR-0019 不开跨弹窗持久化先例）。
- 计数与批量严格跟随当前筛选：「筛选结果 M · 可加入 N」按筛选后结果计，「加入全部」= 当前命中中的可加入。
- 已知限制（接受并文档化，不在本次修）：三档是投影——目录内状态按 ADR-0015 折叠（`isCompleted` → 已结束；值名 `in-progress` → 进行中；其余 → 待办）；改名 `in-progress` 后该档失效且报告的进行中子集同受影响；改状态值名不迁移任务笔记 → 悬空值 → 未知。

## Testing Decisions

- **好的测试只断言外部行为**：给定任务快照、状态目录与筛选状态 → 断言命中集合与计数；不断言 DOM 结构、内部字段形状或渲染顺序。
- **主接缝：选择会话模块**（无 DOM、无 Obsidian 依赖）。全部用户可见语义在这里测：档间 OR、全不选不过滤、三维 AND、未知排除、跨页签保留、筛选不碰报告集合、计数与「加入全部」跟随。先例：该模块既有的行为测试（上一轮「左栏保留筛选结果」修订时建立）。
- **次接缝：状态分类模块**。仅补最小用例：三档折叠规则与悬空值 → 未知。先例：该模块既有测试（目录判定、子集切分）。
- **不测视图装配**：chips 渲染、禁用态、`aria-pressed` 属 DOM 装配，靠原型（已跑通交互）+ 手动核验兜底；**不开 DOM 测试接缝**——仓库没有 DOM 测试框架，为一行 chips 开先例的代价大于收益。
- 行为断言清单（= 验收标准）：
  1. 全不选 → 筛选结果 = 现状（只受区间 / 查询约束）；
  2. 选「进行中」→ 命中恰为归类进行中的任务，点掉即还原；
  3. 选「待办 + 已结束」→ 两者并集，进行中与未知都不出现；
  4. 与区间、查询均为 AND；切页签状态选择保留；
  5. 任一筛选变化后右栏集合与顺序逐项不变；
  6. 状态目录为空 → chip 禁用、列表照常；
  7. 自定义状态按目录归类命中对应档；悬空值任务只在全不选时出现并触发未知提示；
  8. 计数、「加入全部」、空态与筛选结果一致；
  9. 中英文案齐全、`aria-pressed` 与选中态一致（手动核验项）；
  10. 纯函数层测试全绿，typecheck 与 lint 通过。

## Out of Scope

- 列表加"属性列" + 排序：排序 ≠ 筛选；右栏固定按「已加入」顺序，排序与之冲突（ADR-0019/0020）。
- 按优先级 / 项目等其它属性的筛选：本次只做状态，不承诺通用「属性筛选」框架。
- 查询语法糖（`!done` / `status:done`）：会扩张「按标题」查询语法（ADR-0003），留后续单独决策。
- 精确到某个 TaskNotes 状态值的筛选：状态值名可变，本次只筛「归类」。
- 「状态 → 状态归类」映射配置（按状态 id，抗改名）→ [#77](https://github.com/telecomshy/TaskNotesAiReporter/issues/77)。
- `cancelled` / `isSkipped` 类状态的归类修正（影响报告口径）→ [#76](https://github.com/telecomshy/TaskNotesAiReporter/issues/76)。
- 修改任务状态：纯只读筛选。
- 跨弹窗持久化筛选偏好。
- 视图层自动化测试（不开 DOM 接缝）。
