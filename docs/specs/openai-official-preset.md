# OpenAI 官方预设与模型请求策略（max_completion_tokens / 温度 / 清单过滤）

> 权威出处：GitHub issue [#106](https://github.com/telecomshy/TaskNotesAiReporter/issues/106)（`ready-for-agent`）。本文件是仓库内可被 `/code-review` 直接发现的副本，内容取自 issue #106。

> 出处：2026-11-26 经 **`/grill-with-docs`** 四轮逼问定形（Q1–Q11、Q12–Q16 全按推荐；Q17 更正为「**对话模型**」而非「推理模型」）：模型请求策略作为方言之上的第二层窄化（ADR-0030）、只对内置 OpenAI 预设按 id 命中、本轮只走 Chat Completions、温度三态、25k 预算下限、清单在拉取处过滤。事实锚点：`docs/research/openai-official-preset.md`（2026-11-26 官方文档核对）。测试接缝已经用户确认：沿用现有四个缝，不新增。

## Problem Statement

插件只认 OpenAI 兼容方言，但 OpenAI 官方的模型早已换了一套参数脾气，用户想用官方模型写报告时几乎必然踩雷：

1. **额度字段不对。** 官方已把 `max_tokens` 标为 deprecated，定义的「含推理 token 的输出预算」只有 `max_completion_tokens`；插件固定发 `max_tokens`。
2. **温度会被拒。** `GPT-6.2` 恒不允许自定义温度；`GPT-6 Astra` / `GPT-6.1 Sol` 不支持 `none` 档，等效于恒不允许；`GPT-5.2` / `GPT-5.4` 只在 `reasoning_effort: "none"` 时才允许。插件固定发 `temperature: 0.7`。
3. **预算太小。** 推理 token 计入输出预算，官方建议起步预留 25,000 token；插件全局默认 8192，容易出现「只推理、无正文」的空回复。
4. **清单噪声。** `/v1/models` 混入嵌入 / 图像 / 视频 / 语音 / 实时 / 审核模型，且**没有任何能力或端点字段**；直接展示会让下拉大半不可用，也分不清哪些只能走 Responses。
5. **思考开关语义不同。** Chat Completions 上唯一的文档化开关是顶层 `reasoning_effort`（默认 `medium`），`none` 在 `GPT-6 Astra` / `GPT-6.1 Sol` / `GPT-6.2` 上直接 400；插件的能力表对官方模型一无所知。

## Solution

新增「**OpenAI**」内置预设（地址预填、只需选密钥），与其它预设共用同一套「获取模型列表 → 挑选 → 启用 → 当前模型」流程，并引入**模型请求策略**：

- **模型请求策略**叠加在「接口方言」基线上，按（预设, 模型族）决定：输出额度字段名、温度可发条件、输出预算下限、超时下限。方言定基线，策略只能窄化——只对内置预设生效，自定义供应商与四家现有国产预设零变更。
- **请求正确性**：OpenAI 预设统一发 `max_completion_tokens`；推理族按家族规则不发温度；推理族预算下限 25,000、超时下限 120 秒。
- **思考开关**：能力表补 `openai` 行（强制 / 可关 / 无思考），开＝`reasoning_effort:"high"`、关＝`"none"`（不可关的族不发）；候选清单对该预设只探 `reasoning_effort`。
- **清单只收对话模型**：拉取成功后过滤，保留老的非推理对话模型，排除嵌入 / 图像 / 视频 / 语音 / 实时 / 审核与仅 Responses 的模型。
- **无新界面、无新用户配置**：策略是插件内置数据，预设卡与其它预设外观一致。

## User Stories

### OpenAI 官方预设

1. 作为 OpenAI API 用户，我想要一个内置预设且地址已预填，以便我只用选密钥。
2. 作为老用户，我想要升级后自动出现这张预设卡，且原有的供应商、启用集、当前模型一个都不变，以便我可以从容采用。
3. 作为老用户，我想要「补卡」不在载入时强制写盘，以便升级本身不改我的设置文件。
4. 作为用户，我想要 OpenAI 预设与其他预设行为一致（不可删除、同样的拉取 / 挑选 / 已失效 / 未配置清理规则），以便不用重新学一套交互。
5. 作为用户，我想要预设的密钥走 SecretStorage（设置里只存密钥名），以便密钥不落进 `data.json`。
6. 作为用户，我想要清空密钥名后同样回到「未配置 ⇒ 无启用模型」，以便预设之间规则一致。
7. 作为用户，我想要预设卡不显示「接口方言」单选（方言内置固定），以便不会误以为它能切换协议。
8. 作为界面英文 / 中文用户，我想要预设名按界面语言呈现为 `OpenAI`。

### 模型清单

9. 作为用户，我想要清单只出现对话模型，以便下拉不被嵌入 / 图像 / 视频 / 语音 / 实时 / 审核模型塞满。
10. 作为用户，我想要老的非推理对话模型（`gpt-4.1` / `gpt-4o` 关停前）仍可选，以便我手上还有能用的模型。
11. 作为用户，我想要仅 Responses 的模型（`*-pro`、`gpt-oss-*`、`gpt-5.6-cyber`）不出现在清单，以便不会点到必然失败的项。
12. 作为用户，我想要未来新出的对话模型族无需插件更新就能出现，以便模型上新不被卡住。
13. 作为用户，我想要清单过滤后为空时如实报「空清单」，以便不会被误认为拉取失败。
14. 作为用户，我想要清单过滤不改变「已失效」语义：启用模型不在过滤后的清单里仍标「已失效」，可移除、拉回即消。
15. 作为用户，我想要清单顺序原样保留，以便挑选顺序与上游一致。

### 请求正确性

16. 作为用户，我想要输出额度用 `max_completion_tokens`，以便不被 `max_tokens` 的弃用 / 不兼容拒收。
17. 作为 `GPT-6.2` 用户，我想要请求从不带温度，以便不因「不支持自定义值」被拒。
18. 作为 `GPT-6 Astra` / `GPT-6.1 Sol` 用户，我想要请求不带温度，以便不因没有 `none` 档被拒。
19. 作为 `GPT-5.2` / `GPT-5.4` 用户且思考关，我想要温度照发，以便保住 0.7 的文风。
20. 作为 `GPT-5.2` / `GPT-5.4` 用户且思考开，我想要温度不发，以便不触发「非 `none` 即报错」。
21. 作为老对话模型用户，我想要温度照发，以便它们的文风设置继续有效。
22. 作为推理模型用户，我想要输出预算至少 25,000，以便不出现「只推理、无正文」的空回复。
23. 作为老对话模型用户，我想要预算仍取全局值，以便不为非推理模型多花钱。
24. 作为推理模型用户，我想要超时至少 120 秒，以便不被假超时打断。
25. 作为已把全局超时调得更大的用户，我想要更大的值生效，以便我的设置优先。
26. 作为用户，我想要微型探测请求不受 25k 下限影响（仍 256），以便思考测试不烧钱。

### 思考开关

27. 作为用户，我想要常用族一打开就显示正确状态（强制 / 可关 / 无思考），以便不用先跑一次测试。
28. 作为用户，我想要「开」发 `reasoning_effort:"high"`、「关」发 `"none"`，以便开关真的改变推理开销。
29. 作为强制族用户，我想要关态不发 `none`（置灰 + 说明），以便不制造 400。
30. 作为无思考族用户，我想要开关置灰且不发任何思考参数。
31. 作为未登记族（`gpt-5.5`、`gpt-6-cyber`）用户，我想要显示「未知」且测试入口可点，以便不擅自假定。
32. 作为用户，我想要思考测试在该预设上只探 `reasoning_effort`，以便少发无谓的 400。
33. 作为用户，我想要思考测试的基线请求与逐字段请求也遵守同一套策略（不该发的温度不发、超时下限生效）。
34. 作为跑过测试的用户，我想要习得结论优先于内置行，以便模型拒绝时能被纠正。

### 零回归、文档与维护

35. 作为四家现有国产预设的用户，我想要 OpenAI 方言的既有请求形态（`Bearer`、温度、`max_tokens`、`choices[0].message.content`）逐字段不变。
36. 作为自定义供应商用户，我想要我不受任何策略影响（不按地址嗅探官方端点）。
37. 作为自定义 Anthropic 网关用户，我想要本轮完全不动我的路径。
38. 作为读者，我想要 README 的预设清单与网络用途披露写明 OpenAI。
39. 作为维护者，我想要 Responses-only 模型与 Responses API 单开待办，不混进本轮。
40. 作为无密钥的维护者，我想要假响应测试覆盖全部行为，真实生成列入「待密钥验收清单」。

## Implementation Decisions

1. **内置预设补齐**。新增 OpenAI 预设（`id: "openai"`、地址 `https://api.openai.com/v1`、方言 OpenAI 兼容、认证「密钥」）。载入归一化按 id 补齐缺失的内置预设：只追加、不覆盖既有项、不移动既有顺序，**不因补齐落盘**，幂等；全新安装直接由默认设置获得。
2. **预设卡不显示方言单选**（沿用 #105：预设方言内置固定）。
3. **新增「模型请求策略」纯数据模块**：行键（供应商 id, 模型 pattern），与内置思考能力表同构。字段为：输出额度字段名（`max_tokens` / `max_completion_tokens`）、温度规则（`send` / `omit-unless-none` / `omit-always`）、输出预算下限、超时下限。首个命中行生效。
4. **两套缺省**：`openai` 预设未命中时回落「预设缺省策略」（`max_completion_tokens` + `omit-unless-none` + 25,000 + 120）——新模型族无需更新即安全；其它供应商（四家国产预设与自定义）回落空策略（现状：`max_tokens` + `send` + 无下限），保证零变更。
5. **策略解析与思考解析同路**：在「当前模型解析」处产出，随解析结果带出；执行层只消费，不判断供应商类型。生成配置与探测配置各增加可选策略字段；自定义卡的「测试」不传策略。
6. **额度字段**：只有 OpenAI 预设发 `max_completion_tokens`；其余供应商与自定义仍发 `max_tokens`。
7. **预算**：生成请求额度 = 钳制 `max(配置上限, 策略下限)`，钳制上限仍 384K；微型探测恒定 256，不受下限影响。
8. **超时**：生成与探测取 `max(全局超时, 策略下限)`；模型清单拉取不受下限影响。
9. **温度判定输入是「策略 × 本次生效 effort」**，不是用户的开关：生效 effort 由思考解析决定——开＝`high`；关＝能力给出的关参数（`none` 或其它）；强制 / 无思考 / 未知＝不发参数（官方默认 `medium`）。`send` 恒发；`omit-unless-none` 仅在生效 effort 为 `none` 时发；`omit-always` 永不发。
10. **策略行（openai）**：`gpt-6.2*`、`gpt-6-astra`、`gpt-6.1-sol` ＝ `omit-always`；`gpt-4.1*`、`gpt-4o*` ＝ `send` 且无预算下限（非推理）；其余（含 `gpt-5.2*`、`gpt-5.4*`、`gpt-5.6*`、`gpt-6.1-terra*`、`gpt-6-sol*`、`gpt-6-luna*`、`gpt-5.5`、`gpt-6-cyber`）走预设缺省策略。超时下限对预设内全部模型为 120 秒。
11. **思考能力表补 `openai` 行**：强制思考＝`gpt-6-astra`、`gpt-6.1-sol`、`gpt-6.2*`；可关＝`gpt-6.1-terra*`、`gpt-6-sol*`、`gpt-6-luna*`、`gpt-5.2*`、`gpt-5.4*`、`gpt-5.6*`（关 `reasoning_effort:"none"`、开 `"high"`）；无思考＝`gpt-4.1*`、`gpt-4o*`；`gpt-5.5`、`gpt-6-cyber` 不登记＝未知。强制族行须排在通用族行之前（防止被前缀行吞掉）。习得结论仍盖过内置表。
12. **思考测试候选按供应商 id 分派**：`openai` 预设＝单字段 `reasoning_effort:"none"`；其余 OpenAI 方言＝现有三字段；Anthropic 方言不变。状态机（基线 → 逐字段 → 四值判定）与判定规则不变。
13. **清单过滤位置**：拉取成功后、写「模型清单」前，经纯函数过滤；规则按供应商 id 选择，只有 `openai` 有规则。过滤后为空 ⇒ 现有「空清单」结局，照实记账，不新增错误码。
14. **过滤规则（openai）**：粗白名单 `gpt-*` ＋ 排除表（**排除优先**）：非对话族（`text-embedding-*`、`gpt-image-*`、`gpt-realtime-*`、`gpt-live-*`、`gpt-audio-*`、`gpt-transcribe*`、`gpt-4o-transcribe*`、`gpt-4o-mini-tts`、`tts-*`、`whisper-*`、`omni-moderation-*`、`sora*`）、仅 Responses（`*-pro`、`gpt-oss-*`、`gpt-5.6-cyber`）、`chat-latest`（官方不建议 API 使用）。排除表与研究笔记同源维护；模型 ID 顺序原样保留，去重与清洗沿用现有写面。
15. **「已失效」语义不变**：清单是过滤后的完整快照；不在清单的启用模型标「已失效」，可移除、拉回即消；空清单对预设仍是权威结果。清单缺失不构成失效证据。
16. **无新界面、无新用户配置**。文案只新增一个预设名键，双语登记，由现有文案键登记测试间接覆盖。
17. **文档**：README 的预设清单（安装说明、供应商说明、网络用途披露，英 / 中两处）加入 OpenAI；插件与包的描述不变（仍是「OpenAI 兼容或 Anthropic 兼容」）。
18. **Responses-only 与 Responses API 不进本轮**：`*-pro`、`gpt-oss-*`、`gpt-5.6-cyber` 仅从清单排除，另开 `deferred` 待办记录迁移点（`max_output_tokens`、`output[]`）。
19. **错误与状态语义零新增**：沿用 `timeout` / `chat.http` / `chat.network` / `chat.parse` / `chat.empty` / `models.*` 现有词表。

## Testing Decisions

好测试只断言外部行为：从可注入请求函数抓「发了什么」（网址、方法、请求头、请求体），用伪造响应断言「读出了什么」（正文、推理段、清单、错误码），不断言内部函数调用或模块结构。**沿用现有四个缝，不新增。**

- **主缝（沿用）：AI 客户端边界**。以捕获请求 + 伪造响应覆盖：OpenAI 预设发 `max_completion_tokens`、不出现 `max_tokens`；`omit-always` 族不发温度；`omit-unless-none` 族在生效 effort 为 `none` 时发、否则不发；预算取 `max(配置, 25k)`；超时取 `max(全局, 120)`；`reasoning_effort` 参数形状；探测请求同一策略但预算恒 256；四家国产预设的请求体逐字段不变。先例：`test/client.test.ts`。
- **纯函数缝（沿用）：策略表与过滤表**。策略行首个命中、前缀匹配、预设缺省与空缺省；温度判定矩阵（策略 × 生效 effort）；过滤表的白名单 / 排除优先 / 保留 `gpt-4*` 与未来 `gpt-7*` / 排除 `sora*` 与仅 Responses 族；思考候选按供应商 id 分派。先例：`test/thinking.test.ts` 的纯函数段。
- **设置缝（沿用）：归一化与命令门面**。老数据补齐 `openai` 预设（地址 / 方言 / 空密钥名 / bearer）、幂等、不落盘、不动既有项与顺序；未配置 ⇒ 无启用模型；既有「预设集」断言更新。先例：`test/loadSettings.test.ts`、`test/providerSettings.test.ts`。
- **流程缝（沿用）：获取模型列表**。OpenAI 假响应含对话与非对话混合 ID ⇒ 写回的清单只含对话模型、结局为 fetched；全被过滤 ⇒ 结局 empty、清单为空；失败与守卫不写清单；方言透传不变。先例：`test/fetchModelsFlow.test.ts`。
- **UI 人工验收**（无 DOM 视觉测试）：OpenAI 卡片出现且无方言单选、密钥行与其它预设一致；未配置时拉取被守卫拦；思考卡显示「强制 / 可关 / 无思考 / 未知」四态与置灰；焦点环可见。依据 `CODING_STANDARDS.md` § UI。
- **不测**：真实网络与真实模型清单（本机无密钥）；上游拒收的逐字错误文案；文案逐字符内容。

**待有密钥后的验收清单**（本轮不作为验收依据，写进完成评论）：

1. 拉取模型列表：条数合理、无 `text-embedding-*` / `gpt-image-*` / `sora*` / `*-pro`。
2. 选一个推理模型发短请求：返回正文非空，`finish_reason` 不是 `length`。
3. 在可关族上切换思考开 / 关：开时 `reasoning_effort` 发出、关时生效。
4. 在 `GPT-6.2` 一类上确认不发温度、不报 400。

## Out of Scope

- **Responses API** 与仅 Responses 的模型（`*-pro`、`gpt-oss-*`、`gpt-5.6-cyber`）：单开 `deferred` 票。
- 自定义供应商与四家现有国产预设的任何参数变化（含按地址嗅探 `api.openai.com`）。
- 每模型的可视参数行 / 用户可配置的策略；温度、最大输出、超时的设置界面。
- 嵌入 / 图像 / 视频 / 语音 / 实时 / 审核模型的任何支持。
- 思考深度档位（`xhigh` / `max`）与流式、工具调用、结构化输出。
- 组织 / 项目头、OAuth、多 workspace；OpenAI 官方 SDK 的引入。

## Further Notes

- **事实锚点（2026-11-26 官方文档核对，详见 `docs/research/openai-official-preset.md`）**：`/v1/models` 每项只有 `id` / `created` / `object` / `owned_by` / `shutdown_date`，无能力字段，过滤只能靠内置名单；`max_tokens` 已标 deprecated、`max_completion_tokens` 含推理 token；温度规则按族（6.2 恒省、6 Astra / 6.1 Sol 无 `none`、5.2 / 5.4 仅 `none` 时合法）；25,000 预留是官方原文、默认 effort 为 `medium`；Chat Completions 仍支持纯文本（含 GPT-6.2）；`reasoning_effort` 取值 `none…max`，`none` 在 6 Astra / 6.1 Sol / 6.2 上 400；官方**没有**任何延迟或超时数字，120 秒是产品判断。
- **原待办五项如何定案**：模型级参数策略＝策略表（ADR-0030）；清单过滤＝拉取处粗白名单 + 排除表；推理预算＝25k 下限且只对推理族；协议选型＝本轮只走 Chat Completions、Responses 单开；对四家 OpenAI 兼容预设零影响＝策略只按 `providerId` 命中。
