# 规格：「选择模型」下拉不随模型行 / 凭据变更更新——自动目标化重绘

> **部分取代**：本规格的 Implementation Decisions 1–2（视图层窄回调「重绘当前模型卡」、两张供应商卡接收该回调）已由 [ADR-0029](../adr/0029-provider-change-notification.md) 的「供应商门面发布变更、视图按类别失效」取代。用户可见行为与本文档的 User Stories / 验收标准不变；实现接线以 ADR-0029 为准。

> 权威出处：GitHub issue [#107](https://github.com/telecomshy/TaskNotesAiReporter/issues/107)（`ready-for-agent`）。本文件是仓库内可被 `/code-review` 直接发现的副本，内容与 #107 一致。

## Problem Statement

在「模型配置」Tab 的自定义供应商卡里添加 / 改名 / 删除模型行，或改 API 地址、密钥、认证方式之后，顶部「当前模型 → 选择模型」下拉不会跟着变：

- 新加的模型要切一次 Tab（或做别的整页刷新）才出现在下拉里；
- 改名的模型，旧值仍留在选项里、新值不在；
- 删掉的模型仍能被选；
- 清空密钥后，该供应商的模型仍留在选项里。

用户会以为「没保存」，但设置命令本来就即时落盘（ADR-0016：设置 owner 自持状态与落盘）——缺的是**视图重绘**，不是持久化。用户提出的「保存」按钮会把「界面漏刷新」变成用户需要记住的动作，并暗示存在「未保存」状态（本插件没有这一状态）。

## Solution

模型行与凭据变更后，**自动、立即**重绘顶部「当前模型」卡（下拉 + 思考行 + 能力徽标）；不新增按钮、不引入「保存」概念。只重绘顶部这张卡，不动供应商卡的 DOM，所以正在编辑的输入框不失焦、不丢光标。

## User Stories

1. 作为自定义供应商用户，我添加一行模型 ID 后，立刻在「选择模型」下拉里看到它，以便不用切 Tab 才能选。
2. 作为用户，我改名模型后下拉立刻换成新 ID，以便不会选到旧名。
3. 作为用户，我删除模型行后下拉立刻不再列出它，以便列表与配置一致。
4. 作为用户，我改 API 地址后下拉立刻反映该供应商是否仍可选，以便不必猜「为什么选不到」。
5. 作为用户，我改选或清空密钥后下拉立刻反映该供应商是否仍可选。
6. 作为用户，我从「密钥」切到「无认证」或反向时，下拉立刻更新。
7. 作为 Anthropic 兼容网关用户，我切换「接口方言」后下拉立刻更新（语义与其它变更一致）。
8. 作为用户，我编辑模型行的上下文长度 / 最大输出时不希望界面重绘，以便输入不被打断（它们不改变「可选模型集合」）。
9. 作为用户，重绘只发生在顶部卡，我正在编辑的供应商卡输入框保持焦点与光标位置。
10. 作为用户，我不需要点「保存」：改动本来即时生效，下拉也立刻反映。
11. 作为用「获取模型列表 → 挑选确认」的用户，整页刷新语义保持不变。
12. 作为用户，删除供应商 / 切换当前模型 / 思考开关的整页刷新语义保持不变。
13. 作为键盘或读屏用户，重绘后的下拉仍可正常聚焦与展开。
14. 作为 AFK 实现者，我想要一条回归测试证明「新增模型后不切 Tab 就能在下拉里选到它」。

## Implementation Decisions

1. **视图层新增窄回调**「重绘当前模型卡」：顶部「当前模型」区放进独立宿主容器；回调 = 清空宿主 + 按当前解析结果重投一次当前模型投影（同一投影同时刷新下拉、思考行、徽标）。
2. **两张供应商卡接收该回调**：触发点 = 凡是会改变「可选模型集合」的命令——模型行新增 / 改名 / 删除、API 地址、密钥名或密钥值、认证方式；**接口方言切换也触发**（成本低、语义一致）。
3. **不触发**：模型行的上下文长度 / 最大输出参数（不影响可选集合，避免打断输入）。
4. **既有整页刷新路径不变**：挑选确认、删除供应商、切换当前模型、思考开关仍走整页刷新。
5. **不新增「保存」按钮或概念**：设置仍「变更即落盘」（ADR-0016）。**不新增 ADR、不改 `CONTEXT.md` 词汇表**（这是可逆的呈现决定）。
6. **无新文案键**（不新增按钮或提示）。
7. **顶卡重绘与卡内重画互不替代**：顶部回调只动顶部；供应商卡自身的「头部同步 / 行列表重画」只动卡内，两者在同一命令后各做一次。
8. **不自动选模型**：新出现的模型只进入下拉选项，当前模型仍由用户显式选择（ADR-0010 / #87 的「当前模型」语义不变）。
9. 顶部区多一层无样式宿主容器（纯结构，不影响既有 CSS 与展开态账本）。

## Testing Decisions

- **好测试**断言外部可见行为：下拉里是否有该选项、值是否正确；不断言内部函数调用或模块结构，重绘回调改名 / 内联后测试仍应通过。
- **缝（沿用，不新增）**：既有 `renderModelTab` + `FakeEl` 假 DOM 的渲染 / 点击缝，先例 `test/fetchGate.test.ts`（真实渲染 + 触发 `click` / `change` + 断言界面与状态）。
- **覆盖**：
  1. 添加模型行并填入 ID → **不切 Tab**，下拉立刻包含该模型；
  2. 改名模型 → 旧值不在下拉、新值在；
  3. 清空自定义供应商密钥 → 该供应商整组从下拉消失；
  4. 回归网：既有「选择模型」下拉选中、密钥清空联动等用例保持通过。
- **手工验收（无法自动化）**：输入焦点 / 光标位置、键盘 Tab、下拉展开、切方言后高亮。依据 `CODING_STANDARDS.md` § UI。
- **不测**：DOM 视觉与焦点行为（仓库既有约束：无 DOM / 视觉测试）。

## Out of Scope

- 「保存 / 应用」按钮或任何「未保存」状态。
- 其它 Tab、报告弹窗的刷新行为。
- 下拉的交互改版（搜索、分组、异步加载）。
- 自动替用户选中新模型。
- 预设供应商「获取模型列表」流程的刷新语义。
- 思考开关的刷新策略调整。
- 词汇表与 ADR 变更。

## Further Notes

- **复现**：添加自定义供应商 → 填地址与密钥 → 添加模型行并填 ID → 顶部「选择模型」下拉为空；切到「模板配置」再切回才出现。
- **根因**：顶部「当前模型」区与供应商卡在同一帧分别渲染；卡内变更只做「头部同步 / 行列表重画」，顶部投影不重跑；而「获取模型列表 → 挑选确认」走整页刷新，所以那条路径正常。
- **与 #105 的关系**：方言切换纳入触发集合；不改变 #105 已定的方言语义与测试。
- **交付注意**：手工验收项须由人在 Obsidian 中确认，AFK 实现交付时请注明。
