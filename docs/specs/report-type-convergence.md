## Problem Statement

插件产出的每一份报告笔记都带一个 frontmatter `title`，其前缀恒为「报告」。用户在同一段时间生成多份报告后，在 Obsidian 的标签页、快速切换器、搜索结果里看到的是几乎相同的标题（例如「报告 2026-09-09 ~ 2026-09-12」），只能靠日期猜哪份是哪份。**文件名里已经带了模板名**，所以文件列表是可辨的——是标题没跟上。

同一批产出里还有一个 frontmatter `type` 键，恒为同一个定值。它不承载任何信息：按它筛选等于不筛选，按它分组等于只有一个分组。想汇总 AI 生成的报告，需要的是一个真正有判别力的字段——`generator` 键就在旁边。

代码层面还留着一个**四取值的类型与标签表**（周报 / 月报 / 年报 / 报告）。其中**前三档在产品里根本走不到**——主窗口的 `reportType` 字段初始化后全仓无任何赋值点，界面底部只有附加要求输入框、模板下拉与生成按钮；剩下那一档虽然走得到，但**取值恒定**。于是这张表只活在常量与单元测试里，测试反而在为走不到的分支背书，让后来者误以为产品支持「周报 / 月报 / 年报」这类产物类型。

用户的判断是明确的：**周 / 月 / 年只是筛选任务的手段，不是产物的标签**；产物本身就是「一份报告」。

## Solution

让报告的**命名与元信息**跟上「产物不分类型」这个既定事实：

1. **标题可辨**——报告笔记的 `title` 改为「所选模板名 + 日期范围」，与文件名同源；未选模板时模板名位置用「报告」兜底。同一段时间的多份报告因此一眼可分。
2. **元信息只留有信息量的键**——删掉恒定值的 `type` 键。
3. **代码不再假装有四档**——删掉那组四取值的类型与标签表，并把「报告类型」这个入参从**四个环节**（生成编排的用户意图、提示词构造、报告保存、报告文件计划）一并摘掉。
4. **旧模板一字不改**——`{{type}}` 占位符保留，取值改为常量「报告」，沿用既有决策「保留以兼容」。内置默认模板本就不含 `{{type}}`，不受影响。

对用户而言，升级后除「标题变可辨」「少一个 `type` 字段」之外**没有别的变化**：历史报告笔记一律不动，其余行为与设置一律不变。

## User Stories

1. 作为报告读者，我希望报告笔记的标题一眼能认出它讲什么主题、讲哪段时间，以便在标签页和快速切换器里不用靠日期猜。
2. 作为报告读者，我希望标题里的「讲什么」与文件名同源（都取自所选模板名），以便两处看到的是同一回事。
3. 作为报告读者，我希望同一段时间生成的多份报告在列表里彼此可分，以便回看时不混淆。
4. 作为不选模板（极简模式）的用户，我希望标题用「报告」兜底，以便行为可预期、不出现空标题。
5. 作为关心笔记元数据的用户，我希望报告笔记不再写入一个恒定值的 `type` 键，以便属性面板里只留下有信息量的键。
6. 作为想汇总报告的用户，我希望能用 `generator` 键筛出全部 AI 生成的报告，以便有一个真正有判别力的依据。
7. 作为已有历史报告的用户，我希望旧报告笔记一个字都不被改动，以便既有的链接、书签、双链引用继续有效。
8. 作为模板作者，我希望本次改动后所有占位符的行为完全不变，以便我的模板一个字都不用改。
9. 作为用过 `{{type}}` 的老模板作者，我希望它继续可用并渲染成「报告」，以便我的模板文字不塌掉一截。
10. 作为模板作者，我希望模板编辑器里的占位符清单只列出真实可用且有语义的占位符，以便不被引导去用一个永远不变的名称。
11. 作为模板作者，我希望未识别的占位符仍原样保留，以便我写给自己的注记不被吃掉。
12. 作为维护者，我希望那组四取值的类型与标签表从代码里消失，以便不再有人以为产品支持周报 / 月报 / 年报这类产物类型。
13. 作为维护者，我希望「报告类型」这个入参不再在生成编排、提示词构造、报告保存、报告文件计划之间传递，以便调用方不必传无意义的值。
14. 作为维护者，我希望测试断言产品**实际**产出的东西，以便测试不再为走不到的分支背书。
15. 作为维护者，我希望报告文件计划的测试改用「模板名」这个真实输入来验证标题拼装规则，以便不必依赖一个生产里只走单分支的枚举就能钉住结构。
16. 作为维护者，我希望标题拼装规则被「有模板名」与「无模板名」两条用例夹住，以便兜底行为不被未来改动破坏。
17. 作为维护者，我希望术语表与实现保持一致，以便后来者不会读到一个产品里不存在的概念。
18. 作为维护者，我希望既有决策记录补上一条注记，说明 `{{type}}` 现在恒渲染「报告」、与已废弃的术语无关，以便后来者不困惑它为什么还在。
19. 作为用户，我希望升级后除了标题更可辨、少一个 `type` 字段之外没有别的变化，以便升级零风险。
20. 作为用户，我希望本次改动不波及本需求列明之外的任何行为与设置。
21. 作为用户，我希望「选择任务 → 生成报告」的流程、报告写入位置与不覆盖既有笔记的行为不变。
22. 作为用户，我希望时间范围的口径不变（仍取所选任务在**日期口径表内全部字段**上的最早~最晚），以便报告标注的区间与我选的任务跨度一致。

## Implementation Decisions

- **删除四取值残留**：删除那组「报告类型 → 中文标签」的纯数据表与四值联合类型本身。四档里前三档在产品中走不到、剩下那一档取值恒定，整表已失去存在意义。用户所说「只保留自定义」的含义是**产物不再按周期分类型**，而不是保留一个名为「自定义」的枚举值——故类型整体消失，而非收成单值。
- **`{{type}}` 保留、取值改为常量「报告」**：沿用既有决策「保留以兼容」。**不改名、不置空**——占位符替换对未识别名称原样保留，所以真正的删除只能靠「置空」实现，那会让旧模板 `"生成一份{{type}}"` 塌成 `"生成一份"`，属静默的用户可见降级。它恒渲染的「报告」也是准确的（产物就是一份报告）。取值来源由「查标签表」改为**直接的常量**；该常量是中文，与「报告语言」设置无关（与提示词框架文字、文件名兜底的既有做法一致）。
- **入参传递链四环同步收窄**：生成编排的用户意图、提示词构造、报告保存、报告文件计划四处的「报告类型」形参全部移除。注意区分两件事：**标签表的消费处只有两处**（提示词构造、报告文件计划），而**入参形参有四环**（报告保存只是把入参透传给报告文件计划）。
- **frontmatter 删掉 `type` 键**：恒定值零信息。
- **frontmatter `title` 的构成改为「所选模板名 + 日期范围」**：未选模板时模板名位置用「报告」兜底，与文件名的兜底口径一致。日期范围沿用现有口径（所选任务在日期口径表内全部字段上的最早~最晚）。模板名沿用文件名既有的修剪规则（去首尾空白、空则兜底「报告」）。
- **frontmatter 其余键不变**：`start` / `end` / `generatedAt` / `generator`。
- **文件名规则不变**（已经带模板名，本次只是让标题跟上）。
- **模板编辑器的占位符清单不新增 `{{type}}`**：现状即如此，既有决策已定「不写入占位符文档」。
- **补一条决策记录注记**：说明 `{{type}}` 现恒渲染「报告」，与已删除的术语无关。
- **不改写任何既有笔记**：历史报告的 frontmatter 不回填、不迁移。

## Testing Decisions

**什么算好测试**：只断言**外部可见产出**——提示词文本、报告文件计划产出的路径与内容、生成编排的结果。不断言常量表内部结构，不测模块私有函数。

**被测模块**（**全部是既有 seam，本次零新增 seam**，in-process fake / 注入时钟的写法沿用现有先例）：

1. **提示词构造**（纯函数）：`{{type}}` 渲染为「报告」；其余占位符行为不变；未识别占位符原样保留。
2. **报告文件计划**（纯逻辑，注入时钟 / 存在性探测 / 路径规范化）：
   - `title` = 模板名 + 日期范围（**有模板名**一条、**无模板名用「报告」兜底**一条，两条夹住拼装规则）；
   - 产出内容**不再含 `type` 键**；
   - `start` / `end` / `generatedAt` / `generator` 齐备。
3. **生成编排**（fake repository）：去掉「类型」入参后编排仍通过。

**必须更新的既有断言**：
- 提示词测试里「传入 `week` → 断言含『周报』」「传入 `month` → 断言含『类型：月报』」两条，改为断言恒「报告」；
- 报告文件计划测试里以「类型 = `week`」为输入、断言 `title: "周报 …"` 与 `type: week` 的用例，改为**以模板名为输入**驱动标题拼装断言，并补一条断言产出内容不含 `type` 键；
- 生成编排测试里两处显式传 `reportType` 的调用点（一处 `"custom"`、一处 `"week"`）一并去掉该实参。

**回归**：不得破坏既有测试已钉住的不变式（同名冲突追加一次后缀、单一时钟、路径规范化由注入实现决定、正文原样追加在 frontmatter 之后、批补详情缺详情不中断、重入守卫双击只产出一份报告）。
门禁与基线：`npm run typecheck` 通过；`npm run lint`（`--max-warnings 0`）通过；`npm test` 在当前 **285 条**基线之上全绿（本次会净减若干条为类型取值背书的用例、净增标题拼装与不含 `type` 键的用例）。其余路径不得出现任何行为变化。

## Out of Scope

- **报告类型选择器 UI**（周报 / 月报 / 年报下拉）——**不做**。周 / 月 / 年只是筛选任务的手段。
- 让用户自定义标题格式，或新增 `{{title}}` 之类标题占位符。
- 改写历史报告笔记的 frontmatter（不回填、不迁移、不动旧文件）。
- 「日期范围无从推导时的兜底」——既有决策已把它列为另立需求；且当前任务来源下创建日期恒存在（schema required），该回退路径实际不可达。
- 行内任务（Obsidian Tasks）来源相关的一切——已整体移除并提交，不在本需求范围内；**包括其项下的来源改名、按时间筛选提示、默认 Tab 调整、行内任务标记等子决策**。
- `{{type}}` 的改名、删除或语义扩展。

### 为什么保留 `{{type}}` 而不是删掉

既有决策已定「保留以兼容」，该理由至今成立。占位符替换对未识别名称**原样保留**，因此真正删除只能靠置空实现，会让旧模板文字塌掉一截——为删掉一个占位符名付出静默的用户可见降级，不划算。它恒渲染的「报告」也是准确的。

### 为什么删掉 `type` 键是安全的

已对用户 vault 实测（`E:\code\my_projects\shynotes`）：

- **0 个** Dataview / dataviewjs 代码块；
- `.base` 文件 7 个，**全部是任务插件自带视图**（任务列表 / 看板 / 日历 / 日程 / 番茄钟统计 / 关系 / 迷你日历）；
- 命中「`type ==`」的 10 处**全在番茄钟统计视图与任务插件产物里**，语义是番茄钟记录的数组元素字段（`"work"` / `"short-break"` / `"long-break"`），**不是**报告笔记的 `type`；
- 报告笔记现存 3 份，均带 `generator`。

即：**没有任何视图消费报告笔记的 `type` 字段**。且该键恒为定值，本身不可能承载查询语义。

### 风险

- 用户日后若自行写按 `type` 过滤的查询，新报告不会命中。缓解：`generator` 保留且有判别力。
- 历史报告与新报告的 `title` 风格不一致（旧为「报告 + 区间」、新为「模板名 + 区间」）。缓解：不迁移历史文件是明确范围；两者都含同一段日期范围，仍可按时间辨认。

### 措辞约定

新文档不得把「报告类型」当作在用术语；确需指称时写明它是**已废弃的术语**（术语表条目已删除）。
